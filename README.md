# Errand Agent

A chat-based agent for home-service errands like plumbers, electricians, AC servicing and cleaning. It asks only for missing details, compares providers, books, cancels and reschedules with **approval enforced by application code**, and recovers safely from tool failures. Everything runs locally against mocked provider tools.

## Quick start
Needs Python 3.11+ and only the standard library at runtime. Tests use pytest.
```bash
python3 -m venv .venv && .venv/bin/pip install pytest
.venv/bin/pytest -q              # unit + agent + all eval scenarios, offline (scripted model, no network)
.venv/bin/python -m evals.run    # rerun the evals and rewrite evals/results/eval_results.md + eval_table.csv
```

## Live chat (real LLM)
```bash
.venv/bin/python -m errand_agent.cli                                   # default mock environment
.venv/bin/python -m errand_agent.cli --scenario timeout_after_success  # first book() times out after succeeding
#   other scenarios: slot_taken, price_drift, reschedule_conflict
```
Try: `Find a plumber for my kitchen tap this week, mornings only, under 1500 in HSR Layout`, then `book the best rated one`, then `yes`. You can also run `Move my AC servicing to Saturday` or `/provider-cancel <booking id>` followed by `/tick`, and `/memory`, `/remember earliest_time=10:00`, `/forget earliest_time` or `/trace`.

**LLM wiring.** `XAIModel` calls the xAI **Responses API** (`POST https://api.x.ai/v1/responses`) with function tools, `store=false` and low reasoning effort, on `grok-4.7` by default. `models.discover_token()` uses `XAI_API_KEY` first when it is set. Otherwise it uses the same bearer token as the box's shared `grok-agent` CLI: it loads `/home/box/tools/grok-agent/grok_agent.py` and calls its `get_token()`, which returns the pi xAI login with auto-refresh. If that isn't available it falls back to `USER_BEARER_TOKEN`, then `/home/box/secrets/xai_bearer`. The token is never logged, and it is scrubbed from error bodies. Tests and evals never touch the network.

## Layout
| Path | What |
|---|---|
| `errand_agent/mocks/` | The 8 tool contracts from the brief, with a seeded RNG and scenario config. `book` follows the 70/15/15 outcome split, where half the timeouts actually booked. `cancel` returns 503 on the first call. `reschedule` raises `slot_conflict` on configured slots. One injected review per service. |
| `workflow.py` | State enum, transition whitelist, request fields, missing-field logic |
| `approval.py` | Digest-bound approvals and `parse_decision()`, a deterministic user-confirmation parser |
| `executor.py` | Write-ahead op log, idempotency keys, timeout verification, bounded retries, `recover()` |
| `router.py` / `tools.py` | Model-facing tools (no direct side effects) and app-side filtering |
| `agent.py` | Bounded loop, approvals UX, success-claim guard, narrated-action nudge, `tick()` proactive follow-up, `start()` recovery |
| `memory.py`, `memory_seed.py`, `context.py` | Explicit/inferred memory with correct and forget, whole-request token budget |
| `sanitize.py`, `trace.py` | Untrusted text wrapping and injection neutralising, PII redaction, JSONL traces |
| `models.py` | `ScriptedModel` (offline) and `XAIModel` (live) |
| `evals/` | 42 scenarios with simulated users, global invariants and the table generator |
